### FIN-04 · 🔴 Money kernel · L

**Сердце всего плана.** Зависит от FIN-03.

🤖 **Агенту.** Создай `entities/finance/lib/money`:

```
parseMoney(apiValue)      // единственная граница: сырое значение → Money
sum(items, selector)      // вместо reduce((a,c) => a + parseFloat(...))
add / sub / mul
percent(money, rate)      // скидки, ставки — с явным округлением
formatMoney(money)        // единственный форматтер на проект
```

Ограничения:
- Внутри — **целые** минорные единицы или decimal. Плавающей точки нет нигде
- Правило округления **одно**, записано в коде с обоснованием
- **100% покрытие.** Это чистые функции, требование дешёвое и необсуждаемое
- Тесты обязаны включать кейсы, на которых ломается текущий код: `0.1 + 0.2`, суммирование 1000+ строк, деление с остатком при скидках

👤 **Что проверить — здесь ваше знание незаменимо:**
- [ ] **Правило округления верное?** Сейчас 31 `toFixed()` округляют по-разному. Как должна округляться зарплата — вверх, вниз, банковское? Это знает бухгалтерия, не агент
- [ ] **Куда девается остаток** при делении со скидкой? (100 000 / 3 = 33 333.33 × 3 = 99 999.99 — где потерялась копейка и кому она принадлежит)
- [ ] Прочитать `money.test.js` и подтвердить **каждое ожидаемое число**. Не реализацию — ожидания

❓ **Спросить до старта:** правило округления · судьба остатка · формат от API (FIN-03).

## Порядок

```
FIN-01 (роли на бэке?) ─── блокирует расстановку приоритетов
    │
FIN-03 (формат денег) ──▶ FIN-04 (money kernel) ──▶ FIN-08 (миграция расчётов)
                                   │                        │
                                   └──▶ CORE: formatMoney   │
                                                            ▼
FIN-05 (каркас) ──▶ FIN-11 (слоты)              FIN-09 (тесты) ──▶ FIN-10 (распил)
FIN-06 (инвентаризация) ──▶ FIN-07 (консолидация) ──▶ FIN-12 (типы)
```

**Критический путь:** FIN-03 → FIN-04 → FIN-08. Пока нет money kernel, деньги считаются во float, и любая работа в домене строится на неверной арифметике.

## Чего FIN не делает

- Не трогает образовательный домен (ученики, группы, расписание, уроки)
- Не правит `shared/`, `app/`, `widgets/` без ревью CORE (право на PR есть, право на тихую правку — нет)
- Не строит свой HTTP-клиент и свой ui-кит — берёт у CORE, недостающее контрибьютит в `shared/` через ревью
