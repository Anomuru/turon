# 06 — Бэклог Team CORE («Platforma»)

> **Два читателя.** Каждая задача написана дважды: **🤖 агенту** — что делать, где, с какими ограничениями; **👤 разработчику** — что проверить и на какие вопросы ответить.
>
> Контекст холодного старта — [/CLAUDE.md](../../CLAUDE.md). Владение — [03-teams.md](./03-teams.md). Фазы — [04-roadmap.md](./04-roadmap.md).
> Размеры: **S** ≤ 2 дней · **M** ≤ 1 недели · **L** ≤ 2–3 недель.

**Домен:** образовательная часть (ученики, учителя, группы, классы, расписание, dars rejasi, наблюдения, задачи, вакансии, лиды) **плюс вся инфраструктура**, на которой стоят обе команды.

**Двойная роль CORE:** вы не только делаете свои фичи, но и поставляете фундамент для FIN. Обязательство: **PR от FIN в `shared/` ревьюится за один рабочий день.** Иначе денежная команда встанет, а вместе с ней весь план.

### CORE-08 · 🔴 HTTP-клиент · L

🤖 **Агенту.** `shared/api/base.js` — не клиент, а помощники. `useHttp` в **224 файлах**, `catch (e) { throw e }`, заголовки собираются вручную на каждом вызове, обработки 401 нет, 8 закомментированных базовых URL, прод-хост захардкожен.

Новый клиент: базовый URL из env (**не из комментариев**), auth-заголовки автоматически, **refresh по 401 в одном месте**, нормализация ошибок, отмена запросов. Покрыть тестами.

👤 **Что проверить:**
- [ ] Протухший токен → тихий refresh, а не разлогин посреди работы
- [ ] Сервер лёг → пользователь видит внятную ошибку, а не белый экран

❓ **Спросить до старта:** какие есть окружения кроме прода (в файле 8 закомментированных URL — какие из них живые).

### CORE-09 · 🔴 Линт-границы · M

🤖 **Агенту.** Договорённости без автопроверки живут до первого дедлайна. `eslint-plugin-boundaries`:

### CORE-11 · `useSession()` · M
