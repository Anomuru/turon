# 04 — Дорожная карта

> **Про оценки.** Все сроки — при допущении «FIN 2 человека, CORE 3, полная занятость». У проекта нет истории закрытых задач, по которой можно посчитать реальную скорость, поэтому это калибровка, а не обязательство. Пересмотреть после Фазы 0 по факту. Порядок фаз важнее сроков: он продиктован зависимостями, а не желаниями.

---

## Обзор

```
Фаза 0 — Стоп-кран          1–2 нед    ОБЕ КОМАНДЫ ВМЕСТЕ    ← прекращаем делать хуже
Фаза 1 — Граница            3–4 нед    ОБЕ КОМАНДЫ ВМЕСТЕ    ← проводим разделение
Фаза 2 — Передел            2–3 мес    ПАРАЛЛЕЛЬНО           ← команды разъезжаются
Фаза 3 — Закалка            4–6 нед    ПАРАЛЛЕЛЬНО           ← доводим до целевых метрик
```

**Команды разъезжаются только после Фазы 1.** Это не осторожность, а арифметика: пока роуты и меню — единые файлы (38 и 35 коммитов за 6 месяцев), а границы не проверяются линтером, две параллельные команды будут переписывать одно и то же и конфликтовать ежедневно. Попытка «сэкономить» и разъехаться сразу обойдётся дороже, чем месяц совместной работы.

**Работают обе команды вместе. Новых страниц не добавляем.**

| 0.2 | 🔴 Починить RBAC: гарды, `roles` в роутах, 403-страница | CORE | M |
| 0.3 | 🔴 CI на PR: lint + build (тесты — как появятся) | CORE | S |
| 0.4 | 🔴 Защитить `master`: запрет прямого push, обязательный PR + аппрув | CORE | S |
| 0.5 | Ветки по задачам вместо веток по людям; удалить ветку `null` | обе | S |
| 0.6 | Поднять Vitest + RTL, написать первый тест (money kernel — следующая фаза, начать с любой чистой функции) | FIN | S |
| 0.7 | `.github/CODEOWNERS` по матрице из [03-teams.md](./03-teams.md#codeowners) | обе | S |

**0.1 — блокирующая задача и стоит первой не случайно.** Если бэкенд не проверяет роли, то у вас сейчас открытая финансовая система: любой залогиненный пользователь читает бухгалтерию и зарплаты через прямой URL. Это инцидент, который отменяет приоритеты всего остального плана.

**Выход из фазы:**
- [ ] Известно, защищает ли бэкенд деньги (и если нет — заведён инцидент)
- [ ] Учитель по URL `/platform/accounting/...` получает 403, а не бухгалтерию
- [ ] Push в `master` напрямую невозможен
- [ ] PR не мержится с красным линтом
- [ ] `npm test` существует и что-то проверяет
- [ ] Ветки `null` больше нет

## Зависимости между командами

Мест, где одна команда ждёт другую, всего четыре — за этим следить на еженедельном синке:

```
CORE: HTTP-клиент (1.6) ───────────▶ FIN: миграция денежных запросов
CORE: линт-границы (1.7) ──────────▶ обе: граница начинает работать
CORE: модульные роуты (1.5) ───────▶ FIN: свои страницы без конфликтов
FIN:  money kernel (1.1) ──────────▶ CORE: formatMoney вместо toLocaleString
```

Всё остальное — независимо. Это и есть смысл Фазы 1: заплатить месяц совместной работы, чтобы дальше не платить каждый день.

## Если времени меньше, чем в плане

Порядок отказа от задач, если бизнес не даст полный объём. Отрезать снизу:

1. ❌ Бандл и CWV (Ф3) — неприятно, но не смертельно
2. ❌ Миграция 104 слайсов на RTK Query — новый код на RTKQ, старый живёт
3. ❌ Распил god-файлов CORE — работают же
4. ❌ Покрытие 80% по CORE — снизить до «бизнес-логика покрыта»
5. ⚠️ Консолидация бухгалтерии — можно отложить, но платить придётся каждым PR

**Не отрезается никогда:**
- 🔒 RBAC (Фаза 0) — это безопасность
- 🔒 Money kernel + тесты на арифметику — это корректность денег
- 🔒 CI-гейты — это то, что не даёт откатиться назад
- 🔒 Граница между командами (Фаза 1) — без неё разделение на две команды не работает вообще, а именно ради него всё и затевалось
