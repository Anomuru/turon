## 🔴 P0 — Критично

### 1. Ролевого доступа не существует

Это самая серьёзная находка, и она бьёт прямо по деньгам.

**Факты:**

- `src/app/routers/ui/AppRouter.jsx` рендерит **все 87 роутов любому** прошедшему аутентификацию пользователю. Ролевой фильтрации при построении роутера нет.
- `src/app/routers/ui/AppRouter.jsx:48` — `const job = localStorage.getItem("job")` объявлен и **нигде не используется**. Мёртвая строка: кто-то начал делать гейтинг и не закончил.
- `src/app/routers/ui/RequireAuth.jsx` — вся логика проверки ролей **закомментирована** (блок `hasRequiredRoles`, блок `if (!roles.includes(userRoles))`). Компонент проверяет только, что refresh-токен жив, и отдаёт `<Outlet/>`.
- `src/app/routers/ui/RequirePermission.js` — сломан целиком:
  ```js
  export const RequirePermission = ({children, permission}) => {
      if (permission) {
          return children
      }
  }
  ```
  Нет `else`. При отсутствии прав возвращает `undefined` — не редирект, не заглушка, просто пустота.
- `src/app/routers/ui/RequireBranch.jsx` — файл закомментирован **полностью**, от первой строки до последней.
- В конфигах роутов поле `roles:` встречается 4 раза в `routersConfigList.jsx` (на 44 роута) и 3 раза в `routerConfigProfiles.jsx` (на 43 роута) — и **ничто его не читает**.

**Что это значит на практике:** ролевая матрица из [../roles/README.md](../roles/README.md) — красивая таблица, которая описывает только то, что видно в меню. `menuConfig.js` фильтрует пункты меню по ролям (55 упоминаний `roles`) — это косметика. Учитель, набрав `/platform/accounting/...` в адресной строке, попадёт в бухгалтерию.

**Единственное, что сейчас реально защищает деньги, — бэкенд.** Проверяет ли он роли — из этого репозитория не видно. **Это вопрос №1 к бэкенд-команде, и ответ нужен до начала любых работ.** Если ответ «нет» — у вас открытая финансовая система, и это инцидент, а не задача в бэклоге.

### 2. Деньги считаются в плавающей точке

Во всех денежных отчётах суммирование идёт так:

- `src/pages/accountingPage/ui/accountingPages/studentSalary.jsx:61-62` — платежи учеников
- `src/pages/accountingPage/ui/accountingPages/additionalCosts.jsx:230-231` — накладные расходы
- `src/pages/accountingPage/ui/accountingPages/capital.jsx:107-108` — касса
- `src/pages/accountingPage/ui/accountingPages/teacherSalary.jsx:86-88` — зарплаты учителей
- `src/pages/accountingPage/ui/accountingPages/employerSalary.jsx:56-57` — зарплаты сотрудников

```js
const sum1 = capitalList?.reduce((a, c) => a + parseFloat(c.price || 0), 0);
```

`parseFloat` + `+` в цикле по IEEE-754 — это накопление ошибки округления. Плюс 31 вызов `toFixed()` по кодовой базе, который эту ошибку прячет при выводе, но не устраняет в вычислениях. Единого форматтера денег нет: `toLocaleString` вызывается россыпью в 10+ местах, каждый со своими настройками.

Практический эффект: итоги в отчётах расходятся с суммой строк. На больших выборках — на заметные величины. Для бухгалтерии это не «баг с приоритетом medium», это причина не доверять системе.

### 3. CI не проверяет ничего

`.github/workflows/deploy.yml` — единственный workflow:

```yaml
on:
  push:
    branches: [master]
```

Push в `master` → `CI=false npm run build` → SCP на прод-сервер. Ни линта, ни тестов, ни typecheck, ни ревью. `CI=false` вдобавок глушит warnings-as-errors. Деплой идёт по SSH с паролем из секретов.

То есть: **любой коммит в master немедленно уезжает в продакшн без единой проверки.**

### 7. HTTP-слой без слоя

`src/shared/api/base.js` — это не клиент, а набор функций-помощников:

- `useHttp()` — тонкая обёртка над `fetch`, используется в **224 файлах**. Без интерсепторов, без обработки 401, без нормализации ошибок, без ретраев. `catch (e) { throw e }` — то есть буквально ничего.
- `headers()` собирается вручную на каждом вызове; токен читается из `sessionStorage` в каждом.
- В файле — 8 закомментированных базовых URL (`192.168.0.100`, `26.196.249.247`, `localhost:8001`…). Продовый хост захардкожен.
- Обновление токена по 401 не централизовано вообще.

224 места, каждое из которых само решает, как обработать ошибку. Это же 224 места, которые придётся трогать при любой смене контракта.

## 🟡 P2 — Средний приоритет

### 9. Redux: 104 слайса и 104 санки

По слайсу почти на каждую сущность, всё вручную: `createAsyncThunk` → `extraReducers` → `pending/fulfilled/rejected` → селекторы. Это ~104 копии одного и того же шаблона. RTK Query решает ровно эту задачу и уже есть в зависимостях (`@reduxjs/toolkit`).

### 10. Раздутый бандл

В зависимостях одновременно:

- **Три** анимационные библиотеки: `gsap` + `@gsap/react`, `motion`, `framer-motion`
- **Две** карусели: `swiper` + `react-slick` (+ `slick-carousel`)
- `antd` 6 **и** собственная UI-библиотека в `shared/ui` (331 файл)
- `lodash` целиком, `html2canvas`, `react-player`

При целевом бюджете 300 КБ на app-страницу (ваши же правила) это надо мерить и резать.

### 11. ESLint почти выключен

`eslint.config.js` — базовый recommended + react-hooks, и явно:

```js
"no-unused-vars": "off"
```

Правил границ между слоями нет (что естественно — их и не просили). Именно поэтому FSD-структура есть на бумаге, но ничем не защищена: `pages` спокойно импортирует внутренности `entities`.

### 12. Хранилища

196 обращений к `localStorage` / `sessionStorage`. Роль (`job`) читается напрямую в **35 местах**. Токены — в `sessionStorage`, выбранный филиал — в `localStorage`. Единого доступа к сессии нет, каждый компонент лезет в хранилище сам.

`README.md` — это шаблон Vite, закомментированный markdown-ссылками, плюс вставленный кем-то JSON-ответ API с ФИО реальных учителей. Документации по проекту нет. Живой документацией является только `docs/roles/` — и она неплоха.

## Что в проекте хорошо

Чтобы картина не была односторонней:

- **FSD-структура выбрана правильно** и в целом соблюдается. Она — готовый каркас для разделения по доменам; половина работы по проведению границы уже сделана самой структурой.
- **Деньги почти не протекли в `shared/`.** Из 266 «денежных» файлов в `shared/` — ровно 1 (`shared/const/routers.js`, просто константы путей). Это значит, что границу можно провести чисто.
- **`docs/roles/` — качественная документация**, с матрицей доступа и ссылками на строки. Ей можно доверять как описанию *намерения* (даже там, где код это намерение не исполняет).
- **Стек современный** (React 18, Vite 7, RTK) — переезжать на другой не нужно.
- Средний размер файла — 85 строк. Проблема не в «всё плохо», а в 35 конкретных распухших файлах.
