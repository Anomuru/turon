# Turon — контекст для агента

> Читается первым, до любой задачи. Здесь то, что нельзя вывести из кода за разумное время, и то, где код **врёт**.
> План работ — [docs/plan/](./docs/plan/README.md). Роли — [docs/roles/](./docs/roles/README.md).

## Что это

Школьная CRM: ученики, учителя, группы, расписание, планы уроков, наблюдения — **и деньги** (бухгалтерия, касса, зарплаты, займы, инкассация, платежи).

- React 18 + Vite 7, **чистый JS** (не TS), Redux Toolkit, SASS-модули, FSD
- API: `https://school.gennis.uz/api/` (`src/shared/api/base.js`)
- 14 ролей, мультифилиальность
- **Прод живой.** Push в `master` уезжает на сервер немедленно (`.github/workflows/deploy.yml`)

```bash
npm run dev      # разработка
npm run build    # сборка
npm run lint     # ESLint (правила минимальны, no-unused-vars выключен)
# тестов нет — инфраструктура создаётся в Фазе 0
```

## Архитектура

FSD: `app / entities / features / pages / shared / widgets`. 83 592 строк JS/JSX в 980 файлах.

**Главная граница — деньги.** Две команды, два домена:

| Домен | Что |
|---|---|
| **FIN** | Всё, что считает, проводит и записывает деньги |
| **CORE** | Образование + инфраструктура (`shared/`, `app/`, `widgets/`) |

Полная матрица владения — [docs/plan/03-teams.md](./docs/plan/03-teams.md). Зависимость односторонняя: CORE знает про публичный API FIN, FIN про CORE — нет.

## 🔴 Правила денег

**Нарушение любого — блокирующая ошибка ревью.**

1. **Никакой плавающей точки.** `parseFloat`, `Number()`, `+` на суммах — запрещены. Вся арифметика через money kernel (`entities/finance/lib/money`).
2. **`toFixed` / `toLocaleString` на деньгах запрещены.** Форматирование — только `formatMoney`.
3. **CORE не считает деньги вообще.** Показать сумму через `formatMoney` — можно. Сложить две — нельзя.
4. **Денежный код без тестов не мержится.** Арифметика — 100% покрытия.
5. **Слоты FIN принимают только идентификаторы** (`studentId`, `branchId`), не денежные объекты.

## 🔴 Чему в этом коде нельзя доверять

Это не «технический долг», это ловушки. Агент, который поверит коду, сделает неверные выводы:

- **Ролевой доступ не работает.** `RequireAuth.jsx` — проверки ролей закомментированы. `RequirePermission.js` — нет `else`, при отсутствии прав возвращает `undefined`. `RequireBranch.jsx` — закомментирован целиком. `AppRouter.jsx:48` — мёртвая строка. Поле `roles` объявлено в 7 роутах из 87 и **не читается**. **Не считай, что роль где-то проверена.**
- **Меню — не защита.** `menuConfig.js` прячет пункты по ролям. Это косметика: прямой URL открывает всё кому угодно.
- **Деньги считаются во float** по всей бухгалтерии: `reduce((a, c) => a + parseFloat(c.price || 0), 0)`. **Текущие суммы в отчётах неверны.** Не копируй эту логику как эталон.
- **Три параллельные реализации бухгалтерии** — `pages/accountingPage` (4 529 строк, легаси, в проде), `entities/accountingPageNew` (462, недоделана), `pages/accountingPage2.0` (65, заглушка). Перед правкой — уточнить, в какую.
- **`docs/roles/` описывает намерение, а не поведение.** Матрица доступа корректна как ТЗ; код местами ей не соответствует.
- **CI не проверяет ничего** — только собирает и деплоит.

## Подводные камни

- `/api/Overhead/overheads_type/` не работает без query-параметра `branch_id`
- `ROLES.director` = `"direktor"`, `ROLES.main_director` = `"director"` — строки перепутаны, но именно так лежат в localStorage. Не «исправлять»
- Роль читается из `localStorage.getItem("job")` в 35 местах; всего 196 обращений к хранилищам. Токены — в `sessionStorage`
- `useHttp` (`shared/api/base.js`) — не клиент, а обёртка над `fetch`. Нет интерсепторов, нет обработки 401. Используется в 224 файлах
- 104 слайса + 104 `createAsyncThunk` — один и тот же шаблон скопирован 104 раза

## ❓ Что обязательно спрашивать у человека

**Здесь проходит граница моей компетентности.** В этом проекте требования не записаны нигде: ни спек, ни тестов, ни комментариев. Код — не источник истины о том, как **должно** быть; он источник истины о том, как **есть сейчас**, включая баги.

Мой характерный отказ — уверенная правдоподобность: я напишу стройную реализацию и молча потеряю краевой случай, которого никто не помнит. Поэтому спрашивать, а не угадывать:

- **Бизнес-правила расчётов** — как считается зарплата, скидка, долг, пеня. В коде только текущая реализация, и она с багом (float)
- **Ожидаемые суммы в тестах.** Я пишу тест, человек подтверждает число. `expect(sum).toBe(12_500_000)` — это его знание, не моё
- **Правило округления.** Сейчас 31 `toFixed()` округляют по-разному. Какое верно — знает бухгалтерия
- **Формат денег от API** — decimal-строка или число
- **Зачем существует поведение,** которое выглядит как баг. Возможно, это чьё-то требование
- **Кто и что должен видеть,** если `docs/roles/` расходится с кодом

Разделение труда зафиксировано: **код и тесты пишет агент, ожидания подтверждает человек.** Ревью утверждения `expect(...)` стоит секунды и требует знания домена; ревью 800 строк реализации стоит часы и вырождается в «ок». Не менять эти роли местами.

## Конвенции

- Файл > 400 строк — требует обоснования; > 800 — не мержится (сейчас нарушено в 35 и 9 файлах)
- Ветка на задачу, не на человека. Commit — conventional commits
- Не мутировать: новые объекты вместо правки существующих
- Новый server-state — RTK Query, не рукописные санки
- Новые HTTP-вызовы — новый клиент, не `useHttp`
